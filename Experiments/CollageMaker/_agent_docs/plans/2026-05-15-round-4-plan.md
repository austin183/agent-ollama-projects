# Round 4 Implementation Plan

## 1. Panel Editor: Replace Image Selector with Crop Preview

**Files:** `PanelCropEditor.swift`, `CollageViewModel.swift`

**Remove:** The image picker section (`PanelCropEditor.swift` lines 37-78) — both the inline `Picker` (<10 images) and the popover `ImagePickerGrid` (>=10 images). Also remove `@State private var showImagePicker`, `assignedImageIndex`, and `effectiveIndex` binding since they're only used by the picker.

**Add:** A static crop preview that shows:
- The panel's current image scaled to fit the editor width
- A semi-transparent dim overlay: the area inside `sourceRect` is clear (visible), the area outside `sourceRect` is dimmed
- This visually communicates "this is the portion of the image currently shown in the panel"

The overlay math: if the image is displayed at `displaySize`, the visible region is `sourceRect` normalized to `displaySize`:
```
overlayX = sourceRect.origin.x / imageWidth * displaySize.width
overlayY = sourceRect.origin.y / imageHeight * displaySize.height
overlayW = sourceRect.width / imageWidth * displaySize.width
overlayH = sourceRect.height / imageHeight * displaySize.height
```

**Perspective:** The panel's image index is determined by `customImageOrder` + drag-and-drop between panels. Removing the picker prevents duplicate images across panels.

**Edge case:** Handle missing `cropMap` entry (e.g., before saliency completes) — show full image with no overlay.

## 2. Hero Image: Fix `heroIndex` to Actually Affect Layout

**Files:** `LayoutGenerator.swift`

**Problem:** `generateHero()` uses `imageOrder[0]` as the hero image (line 93), ignoring `heroIndex`. The `heroIndex` variable only controls the yellow star in the sidebar.

**Fix:** In `generateHero()`, reorder the image list so the image at `heroIndex` is placed first, then feed the reordered list to the existing layout logic:
- Find `heroIndex` position within `imageOrder`
- Build a new order: `[heroIndex] + remaining images in original order`
- Use this adjusted order for panel assignment

This is a localized change in `LayoutGenerator.generateHero()` — no ViewModel changes needed since `heroIndex` already triggers `regenerateLayout()` via `didSet`.

**Test with:** (a) no custom reorder, (b) after sidebar drag reorder, (c) hero index changed after layout already generated.
