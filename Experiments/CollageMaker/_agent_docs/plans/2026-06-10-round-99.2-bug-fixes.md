## Bug 1: Crop Overlay Does Not Track Canvas Gestures

### Root Cause

`PanelCropEditor.body` accesses `viewModel.cropMap[panel.id]` at line 36, deep inside a `GeometryReader` closure. SwiftUI's `@Observable` dependency tracking establishes observation during `body` evaluation, but when the access is nested inside `GeometryReader`, the dependency may not be reliably registered. The `cropMapVersion` counter increments on canvas gestures, but `PanelCropEditor.body` doesn't re-evaluate because its observation of `cropMap` was not established at the top level.

The `currentCrop` computed property (line 19-21) reads `viewModel.cropMap[panel.id]` but is only used in gesture closures, not in `body`. The `body` passes `viewModel.cropMap[panel.id]` directly to `CropPreviewView`.

### Fix

Hoist the crop binding to the top of `PanelCropEditor.body`, before the `VStack`. This ensures the `@Observable` dependency on `cropMapVersion` is established during the initial top-level body evaluation.

**File:** `Views/PanelCropEditor.swift`

**Before (lines 23-39):**
```swift
var body: some View {
    VStack(alignment: .leading, spacing: 12) {
        Text("Panel Editor")
            ...
            if let image = currentImage {
                GeometryReader { geo in
                    ZStack {
                        CropPreviewView(
                            nsImage: image.nsImage,
                            imageSize: image.size,
                            crop: viewModel.cropMap[panel.id],
                            containerSize: geo.size,
                            panelGeometry: panel.geometry
                        )
```

**After:**
```swift
var body: some View {
    // Establish @Observable dependency at top of body so crop map
    // changes from canvas gestures trigger re-evaluation.
    let crop = viewModel.cropMap[panel.id]

    VStack(alignment: .leading, spacing: 12) {
        Text("Panel Editor")
            ...
            if let image = currentImage {
                GeometryReader { geo in
                    ZStack {
                        CropPreviewView(
                            nsImage: image.nsImage,
                            imageSize: image.size,
                            crop: crop,
                            containerSize: geo.size,
                            panelGeometry: panel.geometry
                        )
```

### Why Not Make CropManager @Observable?

Planner A suggested making `CropManager` `@Observable` and reading through `viewModel.cropManager.cropMap`. This is more invasive:
- Requires adding `@Observable` to `CropManager`
- Changes all read sites across the codebase
- The existing `cropMapVersion` pattern works for all other consumers (canvas preview, panel previews)
- The issue is specific to the `GeometryReader` nesting in `PanelCropEditor`

The hoisting fix is minimal, targeted, and consistent with how the rest of the app uses the version counter pattern.

## Bug 2: Crop Overlay Does Not Align with Panel Content on Select

### Root Cause

`computeQuadInContainer` (two copies: `PanelCropEditor` line 175-181 and `CropPreviewView` line 433-439) maps panel corner positions to container coordinates but **omits the `sourceRect.origin` offset**.

**Current formula:**
```swift
return CGPoint(
    x: fitOffset.x + relX * crop.sourceRect.width / imageSize.width * fittedSize.width,
    y: fitOffset.y + relY_topLeft * crop.sourceRect.height / imageSize.height * fittedSize.height
)
```

This computes where the sourceRect's *size* appears in the container, but not where its *origin* is. It is equivalent to assuming `sourceRect.origin == .zero`.

**Correct formula:**
```swift
return CGPoint(
    x: fitOffset.x + (crop.sourceRect.minX + relX * crop.sourceRect.width) / imageSize.width * fittedSize.width,
    y: fitOffset.y + (crop.sourceRect.minY + relY_topLeft * crop.sourceRect.height) / imageSize.height * fittedSize.height
)
```

**Why the Y-axis is correct as-is (no flip needed):**
- `relY_topLeft = 1.0 - (corner.y - boundingRect.minY) / boundingRect.height` already converts canvas coords (bottom-left origin) to top-left relative position
- `sourceRect` is in CGImage pixel coords (top-left origin)
- The container is in SwiftUI coords (top-left origin)
- The existing `sourceRectInContainer` function maps Y directly without a flip, and its tests pass
- For a rectangular panel, the corrected quad formula produces identical results to `sourceRectInContainer`

**Verification by algebra (rect panel):**
- Top-left corner: `relX = 0`, `relY_topLeft = 0` → `x = fitOffset.x + sourceRect.minX/imageW * fittedW`, `y = fitOffset.y + sourceRect.minY/imageH * fittedH` — matches `sourceRectInContainer`
- Bottom-right corner: `relX = 1`, `relY_topLeft = 1` → `x = fitOffset.x + sourceRect.maxX/imageW * fittedW`, `y = fitOffset.y + sourceRect.maxY/imageH * fittedH` — matches

### Fix

Update both copies of `computeQuadInContainer`.

**File:** `Views/PanelCropEditor.swift`

**Copy 1 — `PanelCropEditor.computeQuadInContainer` (lines 175-182):**
```swift
return corners.map { corner in
    let relX = (corner.x - boundingRect.minX) / boundingRect.width
    let relY_topLeft = 1.0 - (corner.y - boundingRect.minY) / boundingRect.height
    return CGPoint(
        x: fitOffset.x + (crop.sourceRect.minX + relX * crop.sourceRect.width) / imageSize.width * fittedSize.width,
        y: fitOffset.y + (crop.sourceRect.minY + relY_topLeft * crop.sourceRect.height) / imageSize.height * fittedSize.height
    )
}
```

**Copy 2 — `CropPreviewView.computeQuadInContainer` (lines 433-440):**
Same change, same file.

### Note on Planner-g31's Y-flip suggestion

Planner-g31 suggested adding a Y-flip to `sourceRectInContainer` and to the quad computation. This is incorrect. The existing `sourceRectInContainer` tests (e.g., `sourceRectQuarterCropShowsCorrectRegion`) verify that `sourceRect.origin.y = 100` in a 200px image maps to `result.origin.y = 400` in an 800px container — a direct proportional mapping with no flip. Adding a flip would break these tests and break rectangular panel overlays.

## New Test

Add a test to `PanelCropEditorTests.swift` that verifies quad vertex positions match the assembler's render path:

```swift
@Test func quadVerticesAlignWithAssemblerRender() {
    // For a rectangular panel, the quad should match sourceRectInContainer.
    let crop = CropInfo(
        panelId: UUID(),
        sourceRect: CGRect(x: 50, y: 50, width: 100, height: 100),
        destination: PanelGeometry.rect(CGRect(x: 0, y: 0, width: 200, height: 200))
    )
    let imageSize = CGSize(width: 200, height: 200)
    let container = CGSize(width: 400, height: 400)

    // The visible rect should be at (150, 150) with size 200x200
    let visRect = CropManager.sourceRectInContainer(crop, imageSize: imageSize, container: container)
    #expect(visRect.origin.x == 150)
    #expect(visRect.origin.y == 150)
    #expect(visRect.width == 200)
    #expect(visRect.height == 200)
}
```
