## Overview

4 issues in the crop overlay for non-rectangular panel layouts (diagonal slices, hexagonal). Issues #1 and #3 share a root cause. All fixes are in `PanelCropEditor.swift`.

---

## Issue #3 (High Severity): `canvasClipInPanel` Math

**File**: `PanelCropEditor.swift:444-455`

**Root Cause**: `extractPathPoints(cgPath)` returns points in **canvas coordinates**. Verified against `LayoutGenerator.swift`:
- `DiagonalSlicesLayoutStrategy:252-256` — corners use `unshearedRect.origin.x` (canvas X)
- `HexagonalLayoutStrategy:330-332` — centers use `canvasCenter.x + ...` (canvas X)

The current code incorrectly assumes panel-local coordinates and applies a wrong transform:

```swift
// Current (WRONG):
let canvasClipInPanel = CGRect(
    x: -panelFrame.origin.x,
    y: -panelFrame.origin.y,
    width: canvasSize.width + panelFrame.origin.x,    // 1920 + (-212) = 1708 — too small
    height: canvasSize.height + panelFrame.origin.y   // 1080 + 0 = 1080
)
```

For the leftmost diagonal slice panel, `panelFrame.origin.x` is negative (~-212), so the clip rect width shrinks, cutting off the wrong side of the parallelogram.

**Fix**: Since path points are already in canvas coordinates, clip directly to canvas bounds:

```swift
let canvasSize = SizeConstants.defaultCanvasSize
let canvasClipInPanel = CGRect(origin: .zero, size: canvasSize)
```

Also update the misleading comment on lines 444-448.

## Issue #1: Diagonal Slices Hourglass

**Resolution**: Fixed as a direct consequence of fixing Issue #3. With the correct `CGRect(origin: .zero, size: canvasSize)` clip rect, the Sutherland-Hodgman algorithm will properly clip the leftmost parallelogram at the canvas left edge, producing the correct clipped triangle shape instead of the hourglass.

## Issue #2: Hexagonal Layout Corner Resize

**File**: `PanelCropEditor.swift:615-663` (detectDragMode), `:48-107` (gesture handler), `:395-419` (handles)

**Root Cause**: Two problems:
1. **Line 638**: `if vertices.count == 4` guard blocks resize for hexagons (6 vertices)
2. **Lines 76-82**: `dragBaseOrigin` / `dragBaseSize` are only set for `.rect` visible regions — when `.quad` is detected, the anchor math in `handleResize` uses `.zero`

**Fix Strategy**: Use the **crop source rectangle projection** (visible rect in container space) for resize handles on ALL panel types. The source rect is what resize actually modifies, so its corners are the natural handle positions.

### Changes:

**A. Gesture handler** (lines 48-107):
- Always compute `sourceRectProj` via `CropPreviewView.computeVisibleRect` for both `.rect` and `.path` geometries
- Set `dragBaseOrigin` and `dragBaseSize` from `sourceRectProj` for all panel types
- Pass `sourceRectProj` into `detectDragMode`

**B. `detectDragMode`** (lines 615-663):
- Change signature to accept `sourceRectProj: CGRect`
- Remove `vertices.count == 4` guard
- Use `sourceRectProj` corners for all resize handle distance checks
- Keep polygon containment test for `.drag` mode

**C. `visibleRegionHandles`** (lines 395-419):
- For `.quad`, compute handle positions from `computeVisibleRect` corners instead of polygon vertices
- This ensures the 4 orange handles appear at the resize-able corners of the crop rect, regardless of panel shape

## Issue #4: Dead `clipEdge` Function

**File**: `PanelCropEditor.swift:481-508`

**Root Cause**: The `clipEdge` inner function is defined but never called — only `clipEdgeCorrect` (lines 511-535) is used. Additionally, `clipEdge` has a bug: `prev` is declared as `let` and never updated in the loop.

**Fix**: Delete lines 481-508 entirely.

## Risks & Considerations

- **Coordinate systems**: The learning file `polygon-clip-and-vertex-guard-propagation.md` previously documented the canvas-in-panel-coordinates formula as correct. The change request correctly identifies that the path points are in canvas coordinates, not panel coordinates. Verified against `LayoutGenerator.swift`.
- **Handle positions for hex panels**: After the fix, orange handles will appear at the 4 corners of the crop rectangle, not at the 6 hex vertices. This is correct — resize operates on the crop rect, not the panel shape.
- **Vertex-count guard propagation**: The learning file warns about searching for `vertices.count == N` across all files. Verified `detectDragMode` is the only remaining location with this pattern.
- **`handleResize` anchor math**: Currently uses `dragBaseOrigin` / `dragBaseSize` which are only set for `.rect`. The fix ensures they are set for `.quad` as well, using the `sourceRectProj`.
