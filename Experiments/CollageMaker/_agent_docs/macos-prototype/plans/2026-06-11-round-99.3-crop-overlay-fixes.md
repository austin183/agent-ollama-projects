# 2026-06-11 Round 99.3 — Crop Overlay Misalignment Bug Fixes

**Date:** 2026-06-11
**Source:** `_agent_docs/change-requests/round-99.3.md`
**Goal:** Fix two crop overlay rendering bugs introduced by the shape-aware crop overlay feature (plan: `2026-06-10-shape-aware-crop-overlay.md`).

---

## Issues

1. **Diagonal Slices — overlay not clipped to canvas edge.** When a panel is clipped because it reaches the canvas boundary, the crop overlay still shows the full unclipped parallelogram shape instead of the clipped triangle.

2. **Hexagonal Layout — overlay renders as X/hourglass.** The crop overlay appears as a criss-cross shape instead of a hexagon.

---

## Root Cause Analysis

### Issue 1 — Missing Clip

In `CollageEditorView.swift:136`, the collage preview is clipped to the canvas frame with `.clipShape(RoundedRectangle(cornerRadius: 0))`. This correctly clips panel geometry that extends beyond canvas bounds.

In `CropPreviewView` (`PanelCropEditor.swift:386-401`), the `dimOverlay` and `strokeVisibleRegion` are drawn from the full `cgPath` of the panel destination. The overlay elements are **not** clipped to the container bounds, so the dark overlay "hole" reveals the full parallelogram even when the image beneath is clipped.

### Issue 2 — Quad-Only Guard + Fallback Bug

Both `computeQuadInContainer` methods (`PanelCropEditor.swift:169` and `CropPreviewView:427`) contain:

```swift
guard corners.count == 4 else { ... fallback rectangle ... }
```

Hexagonal panels have **6 vertices**, so the guard fails and the fallback executes. The fallback returns 4 points in order `[TL, TR, BL, BR]`. When connected sequentially (TL → TR → BL → BR → close), this draws a criss-cross / hourglass path instead of a rectangle.

---

## Execution Order

### Step 1 — Remove Quad-Only Guard (Fixes hexagonal X/hourglass)

**File:** `PanelCropEditor.swift`

**Changes:**

1. **`PanelCropEditor.computeQuadInContainer` (line 169):** Remove `guard corners.count == 4`. The coordinate mapping loop on lines 179-186 already works for any number of vertices — it maps each `CGPoint` from the `cgPath` to container space independently.

2. **`CropPreviewView.computeQuadInContainer` (line 427):** Same change — remove `guard corners.count == 4`. The mapping loop on lines 337-444 handles N vertices.

**After removal, the fallback rectangle code becomes unreachable** (the only other guard failure is when `boundingRect` is zero-sized or `cgPath` is nil, which would be a data error). Can leave the fallback as a safety net or remove it.

**Verification:** Build succeeds. Hexagonal panels in crop preview render as hexagons.

---

### Step 2 — Clip Overlay to Container Bounds (Fixes diagonal slices clipping)

**File:** `PanelCropEditor.swift`

**Changes:**

In `CropPreviewView.body` (lines 386-401), wrap the overlay views in a clip to the container size:

```swift
var body: some View {
    ZStack {
        Image(nsImage: nsImage)
            .resizable()
            .aspectRatio(contentMode: .fit)
            .frame(width: containerSize.width, height: containerSize.height)
            .clipped()

        if let crop {
            let region = computeVisibleRegion(crop, container: containerSize)
            ZStack {
                dimOverlay(region: region, container: containerSize)
                strokeVisibleRegion(region)
                visibleRegionHandles(region)
            }
            .frame(width: containerSize.width, height: containerSize.height)
            .clipped()
        }
    }
}
```

This ensures the dim overlay cutout, white stroke, and handle dots are all clipped to the virtual canvas bounds — matching what `CollageEditorView` does at line 136.

**Verification:** Diagonal Slices panels that are edge-clipped now show a cropped overlay that matches the visible triangle.

---

### Step 3 — Harden Empty Vertices Guard

**File:** `PanelCropEditor.swift`

**Changes:**

In `dimOverlay` (line 480), `strokeVisibleRegion` (line 500), and `visibleRegionHandles` (line 526), add guards against empty `vertices` arrays before accessing `vertices[0]`:

- `dimOverlay` / `strokeVisibleRegion`: guard `!vertices.isEmpty` before `path.move(to: vertices[0])`
- `visibleRegionHandles`: the `ForEach(vertices.indices, ...)` already handles empty gracefully, no change needed

**Verification:** No crash on edge cases.

---

### Step 4 — Consolidate Duplicate Code (Cleanup)

**File:** `PanelCropEditor.swift`

The `extractPathPoints` and `computeQuadInContainer` functions are duplicated between `PanelCropEditor` (lines 154-214) and `CropPreviewView` (lines 412-472). Consolidate:

1. Move `extractPathPoints` to a static method on `CropPreviewView`
2. Move `computeQuadInContainer` to a static method on `CropPreviewView` (taking `imageSize` as a parameter)
3. Have `PanelCropEditor` call through to the static methods

**Verification:** Build succeeds, behavior unchanged.

## Risks

| Risk | Mitigation |
|------|-----------|
| Removing `guard corners.count == 4` breaks non-quad, non-hex shapes | The mapping loop is vertex-agnostic; any polygon works |
| Clipping overlay removes visible handles at edge | Handles at the exact edge are already visually ambiguous; clipping matches editor behavior |
| Drag gesture hit-testing affected by clip | `.clipped()` only affects rendering, not hit testing |
