# Round 3: Multiline Title, Font Controls, and Panel Drag Reorder

## Source Request

> **Title**
> - Make Multiline
> - Introduce Font Controls (Font, size, style options)
>
> **Panel Arrangement**
> - Clicking and dragging a panel should pick up the panel and rearrange the panels around it so it can be dropped back into a different place on the panel grid

---

## Phase 1: Multiline Title + Font Controls

**Scope:** ExportPanel UI + ViewModel state + Assembler rendering. No canvas interaction.

### New File: `Models/TitleStyle.swift`

A `TitleStyle` struct holding all title rendering options:

```swift
struct TitleStyle: Codable, Equatable {
    var fontFamily: String    // NSFont family name; empty = system default
    var fontSize: CGFloat     // 12–120pt, default 48
    var fontColor: NSColor    // default white 80% alpha
    var alignment: NSTextAlignment  // default .center
    var showBackground: Bool  // default true

    static let `default` = TitleStyle(
        fontFamily: "",
        fontSize: 48,
        fontColor: NSColor.white.withAlphaComponent(0.8),
        alignment: .center,
        showBackground: true
    )
}
```

UserDefaults persistence helpers to archive/unarchive `NSColor` and serialize the struct as JSON.

### Modify: `CollageViewModel.swift`

- Add `titleStyle: TitleStyle` property (persisted to UserDefaults, triggers `updatePreview()` on change)
- Pass new title params (`titleStyle`) to assembler in `updatePreview()` and `exportCollage()`
- Add `UserDefaultsKeys` entries for title style properties

### Modify: `CollageAssembler.swift`

- Update `CollageAssembly` protocol: both `assemble*` methods accept `titleStyle: TitleStyle` instead of plain `title: String` alone
- Update `CollageAssembler` implementations to forward the new parameter
- Update `drawTitle()` to:
  - Use `NSFont(name: titleStyle.fontFamily, size: titleStyle.fontSize)` with `NSFont.boldSystemFont(ofSize:)` fallback when font name is empty or unavailable
  - Use `NSParagraphStyle` for alignment
  - Use `titleStyle.fontColor` for text color
  - Conditionally draw background based on `titleStyle.showBackground`
  - Keep existing bounding box calculation and centering logic

### Modify: `ExportPanel.swift`

Replace the current single-line `TextField` with:

1. **`TextArea`** — multiline title input
2. **New "Title Style" section** with:
   - Font picker: `Menu` + `Picker` listing all `NSFontManager.shared.availableFonts`
   - Size slider: 12–120pt, labeled with current value
   - Color picker: reuse existing `NSColorPickerView` NSViewRepresentable pattern
   - Alignment: segmented control (left / center / right)
   - Background: toggle switch for `showBackground`

### Risk Assessment

**Low.** Pure UI + rendering change. No gesture conflicts. Existing title functionality is a straightforward superset.

## Phase 2: Title Drag-to-Position on Canvas

**Scope:** Canvas interaction for free-form title positioning.

### Modify: `Models/TitleStyle.swift`

- Add `positionX`, `positionY: CGFloat` — normalized 0–1 coordinates for title placement on canvas
- Default: center-bottom (`0.5, canvasHeight - titleHeight - 20` normalized)

### Modify: `CollageViewModel.swift`

- Add `isDraggingTitle: Bool` for canvas state

### Modify: `CollageAssembler.swift`

- `drawTitle()` uses `positionX/Y` to place title anchor point instead of hardcoded bottom-center calculation
- Alignment still applies relative to the anchor point (left = anchor is left edge, center = anchor is center, etc.)

### Modify: `CollageEditorView.swift`

- Compute `scaledTitleFrame` from `positionX/Y` and title bounding box (estimated from font size)
- Overlay grabber handle (⠿ icon) over title region on hover
- `DragGesture` on title hit area moves `positionX/Y` live during `onChanged`, commits on `onEnded`
- Title hit area is distinct from panel hit areas (title rendered on top layer)

### Risk Assessment

**Medium.** New gesture on canvas, but title is a distinct region from panels. Minimal conflict with existing pinch-zoom (different activation — grabber handle vs. trackpad pinch).

## Phase 3: Panel Drag-to-Reorder

**Scope:** Canvas interaction for swapping images between panels.

### Modify: `CollageViewModel.swift`

- Add `customImageOrder: [Int]` — a permutation of image indices (persisted as JSON to UserDefaults)
- `swapPanelImages(sourceId: UUID, targetId: UUID)` — finds both panels in `panels` array by ID, swaps their corresponding entries in `customImageOrder`, calls `updatePreview()`
- `regenerateLayout()` uses `customImageOrder` to map layout slots → image indices. Resets `customImageOrder` automatically when image count changes
- `moveImages()` (sidebar reorder) updates `customImageOrder` to reflect new image order

### Modify: `LayoutGenerator.swift`

- Add optional `imageOrder: [Int]?` parameter to `generate()`
- When provided, slot `i` gets `imageOrder[i]` instead of index `i`
- Propagates through all three layout styles (uniform, hero, mosaic)

### Modify: `CollageEditorView.swift`

- Add drag state: `@State dragSourcePanelId: UUID?`, `@State dragTargetPanelId: UUID?`, `@State dragCursorLocation: CGPoint?`
- Add `DragGesture` (minDistance: 5, minDuration: 0.15) at ZStack level:
  - `onChanged`: hit-test `scaledPanelFrames` to update `dragTargetPanelId`
  - `onEnded`: call `viewModel.swapPanelImages(sourceId, targetId)`
- Visual feedback:
  - Cyan stroke on drag source panel
  - Green stroke on drag target panel (hover)
  - Semi-transparent ghost overlay follows cursor
- Uses `minimumDistance`/`minimumDuration` to not conflict with tap-to-select
- Does NOT conflict with scroll-wheel pan or pinch-zoom (different input modalities)

### Risk Assessment

**Medium.** Gesture layering with existing pinch-zoom and scroll-pan, but different input modalities (mouse drag vs. scroll wheel vs. trackpad pinch). `minimumDistance` threshold prevents tap-to-select conflict.
