# Skill Extraction Preamble

## Overview

This file serves as a general preamble for extracting skills from reference markdown documents. Use this template when you need to extract a skill from any markdown document following the skill-extraction skill guidelines.

## Purpose

This preamble provides guidance on:
- What information to extract from the source document
- How to structure the extracted skill content
- Quality standards for the output
- Common pitfalls to avoid

## Extraction Guidelines

### Focus Areas
Identify the primary areas this skill addresses:
- Technical implementation
- Problem-solving approaches
- Tool usage and configuration
- Best practices and patterns
- Common workflows

### Key Topics
Extract specific, concrete topics:
- API endpoints or functions
- Configuration options
- Command-line usage
- File formats and structures
- Error handling patterns

### Use Cases
Determine when to apply this skill:
- Debugging specific issues
- Implementing features
- Optimizing performance
- Setting up environments
- Troubleshooting problems

### Related Plan Sections
Identify section names from the source document:
- Technical implementation details
- Setup procedures
- Configuration guidelines
- Troubleshooting sections
- Best practices

## Quality Standards

1. **Concise Description** (under 100 characters)
   - Use third-person perspective
   - Describe what the skill does
   - Avoid vague language

2. **Actionable Instructions**
   - Each step should be specific and clear
   - Include exact commands, paths, and URLs
   - Use numbered procedures for step-by-step instructions

3. **Code Examples**
   - Include actual code snippets
   - Use proper syntax highlighting
   - Show expected terminal output when relevant

4. **Configuration Details**
   - Preserve exact paths, URLs, and commands
   - Include version numbers when relevant
   - Document environment-specific settings

5. **Troubleshooting**
   - Identify common problems
   - Provide concrete solutions
   - Include error messages and their meanings

6. **Tips**
   - Share best practices
   - Highlight important notes
   - Mention gotchas or edge cases

## Common Pitfalls to Avoid

1. Including project-specific context instead of skill-specific content
2. Writing vague, high-level descriptions
3. Omitting concrete implementation details
4. Not preserving exact commands and paths
5. Forgetting to include troubleshooting tips
6. Using inconsistent terminology

## Output Format

The extracted skill should be formatted as a complete markdown document with all required sections. Follow the template structure exactly and ensure all fields are filled with relevant, actionable information extracted from the source document.
